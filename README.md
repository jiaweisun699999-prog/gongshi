# 共事之间 · Gongshi

**让每一份用心，被看见。**

一个面向内部团队的同事互评 Web 应用。记录共事中的具体行为与感受，通过 GPT 整理协作特点、优势和改进建议，让同事更了解彼此，也帮助自己看见成长的方向。

界面以写实房间为背景，结合暖色毛玻璃、柔焦和轻量交互。文字反馈是主要输入，量表和工作观察作为补充。

场景切换会先准备并解码新图片，再在完整旧画面上淡入；快速连续点击时以最后选择的房间为准。未显示的场景隐藏，减少全屏模糊图层的合成开销。图片加载失败时保留原画面，可再次点击重试。

## 功能

| 空间 | 可以做什么 |
| --- | --- |
| 客厅 | 了解项目，进入个人报告、同事互评和同事广场 |
| 卧室 | 查看收到的反馈汇总，按维度了解优势和建议，展开每条评价的原文与量表 |
| 私人会议室 | 搜索同事、填写文字、补充工作风格与协作表现，确认赞踩，保存草稿或提交互评 |
| 户外庭院 | 搜索和浏览同事卡片，查看好评率、工作风格、协作能力和职业行为的汇总 |
| 管理后台 | 独立登录后创建同事账号、修改显示名称、重置密码、停用或重新启用账号 |

- 同事选择器支持搜索、下拉滚动和加载更多。
- 庭院和管理员账号列表支持搜索与分页，每页最多 20 人。
- 用户名按钮展开后可以退出登录，登录页面也支持全屏。
- 管理员入口通过直接访问 `/admin` 打开。管理员账号不出现在互评对象和庭院中。

## 本地运行

### 环境

项目已在 **Node.js 24.14.0** 上验证。需要支持 `node:sqlite`、内置 `fetch` 和 `--env-file` 的 Node.js 环境。

项目使用 Node.js 内置模块，当前没有第三方运行依赖，也没有前端构建步骤。

### 1. 配置环境变量

进入仓库根目录，新建 `.env` 文件，填写自己的 OpenAI API 密钥。

```dotenv
OPENAI_API_KEY=replace-with-your-openai-api-key
OPENAI_MODEL=gpt-5-mini
PORT=4173
```

`.env` 已列入 Git 忽略规则。密钥由后端读取。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `OPENAI_API_KEY` | 未设置 | 用于文字分析和汇总的 OpenAI API 密钥 |
| `OPENAI_MODEL` | `gpt-5-mini` | 模型需要支持 Responses API、结构化输出及当前请求中的推理参数 |
| `PORT` | `4173` | 本地 HTTP 服务端口 |
| `HUPING_DB` | `.huping-data/reviews.sqlite` | SQLite 数据库路径，相对路径基于启动命令的工作目录 |
| `PUBLIC_ORIGIN` | 未设置 | 远程部署的完整站点来源，例如 `https://aidatamind.cn`；配置后允许该 Host、校验同源请求，并为 HTTPS 登录 Cookie 添加 Secure |

未配置密钥时，登录、账号管理、互评保存等功能仍可使用；需要调用 GPT 的分析操作会提示配置密钥。

### 2. 启动服务

```sh
node --env-file=.env --use-env-proxy server.mjs
```

打开 [用户登录页](http://127.0.0.1:4173/login)。以上链接使用默认端口。

开发时可以开启文件监听，后端文件修改后自动重启。

```sh
node --env-file=.env --use-env-proxy --watch server.mjs
```

`--use-env-proxy` 让 Node.js 使用当前环境中的代理配置。密钥和环境变量变更后，需要重新启动服务进程。

### 3. 首次设置管理员

保持服务运行，在另一个终端、同一仓库根目录执行。

```sh
node --env-file=.env server.mjs --setup
```

命令会输出一条包含一次性令牌的本地初始化链接。打开该链接，填写管理员显示名称、登录名和密码，即可创建管理员并登录后台。

- 初始化链接有效期为 24 小时，使用后失效；重新执行命令会替换旧令牌。
- 已有管理员时，初始化命令会提示管理员已设置。
- 登录名以英文字母开头，可包含字母、数字、点、连字符和下划线，长度为 3–32 个字符。
- 创建或重置密码时，密码长度为 12–128 个字符。

后续通过 [管理员页面](http://127.0.0.1:4173/admin) 输入管理员账号和密码登录。后台登录会话与普通用户会话独立。

### 4. 创建同事账号并体验互评

1. 管理员创建至少三个同事账号，并将登录名和初始密码分别交给对应同事。
2. 使用其中两个账号，在私人会议室给第三个账号提交文字反馈。
3. 使用收到评价的账号进入卧室，点击「查看我的反馈」。
4. 收到至少两位同事的文字反馈后，首次打开报告会尝试生成 GPT 汇总。收到新反馈时，可以更新报告。
5. 在庭院展开同事卡片，查看有足够共同观察支持的工作表现汇总。

不同账号可以使用不同浏览器或独立浏览器配置同时体验。在同一个浏览器会话内切换账号时，其他标签页会同步更新登录状态。

**新克隆的仓库没有预置账号、测试密码和评价数据。** 本地试用时创建的数据保存在数据库中。

## 阿里云部署

本次部署使用独立的正式数据库，没有导入本地测试账号、评价和报告。

| 项目 | 配置 |
| --- | --- |
| 用户入口 | [https://aidatamind.cn](https://aidatamind.cn) |
| 管理后台 | [https://aidatamind.cn/admin](https://aidatamind.cn/admin)，不在用户界面显示入口 |
| 域名解析 | `aidatamind.cn` 和 `www.aidatamind.cn` 的 A 记录指向 `43.108.80.68` |
| HTTPS | Caddy 2.11.9 自动申请和续期证书，HTTP 跳转 HTTPS，`www` 跳转主域名 |
| 应用运行 | Node.js 24.22.3，监听 `127.0.0.1:4173`，由 Caddy 转发 |
| 程序目录 | `/opt/gongshi/releases/` 保存版本，`/opt/gongshi/current` 指向当前版本 |
| 正式数据 | `/var/lib/gongshi/reviews.sqlite`，与程序版本分开保存 |
| 后端配置 | `/etc/gongshi/environment`，权限 `600`，仅 root 可读 |
| 进程管理 | `gongshi.service` 和 `caddy.service`，均已设置开机启动 |
| 数据备份 | `/etc/cron.daily/gongshi-backup` 每日执行，备份到 `/var/backups/gongshi/`，保留约 14 天 |

服务器为 CentOS 7，使用独立的 musl 运行库兼容 Node.js，没有替换系统 glibc。后续建议迁移到受支持的新系统；运行环境与代理需定期更新。

生产环境变量的无密钥模板见 [deploy/environment.example](deploy/environment.example)。实际密钥只保存在服务器配置文件中，修改后执行 `systemctl restart gongshi`。

首次设置管理员需要通过 SSH 生成一次性链接，链接本身不要写入文档或提交到 Git：

```sh
cd /opt/gongshi/current
sudo -u gongshi env HUPING_DB=/var/lib/gongshi/reviews.sqlite PUBLIC_ORIGIN=https://aidatamind.cn /opt/gongshi/bin/node server.mjs --setup
```

打开命令输出的链接设置管理员，再在后台创建正式同事账号。初始化链接有效期 24 小时，使用一次后失效；已有管理员时直接访问 `/admin` 登录。

常用维护命令：

```sh
systemctl status gongshi caddy
journalctl -u gongshi -n 50 --no-pager
systemctl restart gongshi
systemctl reload caddy
/etc/cron.daily/gongshi-backup
```

更新时只上传程序与素材到新版本目录，切换 `current` 后重启应用，保留原有配置文件和正式数据库。不要上传本地 `.env`、`.huping-data/` 或 `.git/`。回滚、恢复和服务配置详见 [部署说明](deploy/README.md)。

房间图片使用内容哈希作为 URL 的 `v` 参数，匹配当前内容时允许浏览器长期缓存；未带版本的图片缓存一小时。页面和脚本仍需校验更新，静态文件支持 ETag 和 `304` 响应，API 继续使用 `no-store`。替换背景素材时，应同步更新 `styles.css` 中图片 URL 的哈希前 12 位，以及 `index.html` 中客厅图片的预载 URL。

## 评价与汇总

### 互评输入

- 文字反馈建议描述具体场景、对方的行为，以及对合作产生的影响。
- 可补充工作风格、协作能力和职业行为的具体观察，每项最多 400 字。
- 可填写信息同步、交付跟进、问题解决和协作支持四个量表维度，每项使用 1–5 分或「未观察到」。
- 正式提交前需要确认「赞」或「踩」。每次提交新增一条独立评价，不覆盖之前的内容；成功后清空表单，方便记录下一次合作。网络重试不会重复保存同一次提交。
- 草稿按评价对象独立保存，可以继续修改。私人会议室可展开「我给 TA 的历次反馈」，每页 20 条；卧室可以查看收到的所有评价原文和提交时间。
- 旧版本升级会保留当时仍存在的正式评价和草稿，旧评价时间显示为「时间未记录」。已在旧版本中被覆盖的内容不能通过此次升级自动恢复。

### GPT 整理

后端通过 OpenAI Responses API 请求结构化结果，当前默认模型为 `gpt-5-mini`。

- 单条分析整理行为、影响和建议。行为与影响需要通过原文片段核验；信息笼统时会引导补充具体事例。
- 个人汇总需要至少两位不同同事的文字反馈。同一位同事的多次反馈都参与归纳，但合并为一个来源，不会被误算为多位同事。
- 协作特点和庭院中的共享标签需要至少两位同事的原文证据支持。
- 量表分数由程序按历次有效评分计算，「未观察到」排除在均分之外；单个维度不足两位不同同事评分时显示样本不足。
- 好评率按历次正式评价的 `赞 ÷（赞 + 踩）× 100%` 计算，并展示有效票数；同一位同事的多次正式评价分别计票。草稿和未确认赞踩的旧评价不计入。
- 汇总结果会缓存；反馈文字变化后标记待更新。模型结果仍需结合具体合作场景理解。

提交的文字会发送给 OpenAI 分析，API 请求设置了 `store: false`。该请求参数不代表对服务提供方全部数据保留政策的说明。

## 数据与访问范围

| 内容 | 应用中的访问范围 |
| --- | --- |
| 自己写的草稿与已提交互评 | 对应评价者登录后查看 |
| 收到的评价原文、量表和个人报告 | 收件人登录后查看 |
| 庭院卡片中的共享汇总和好评率 | 已登录的同事查看 |
| 同事账号的创建、重置密码和状态管理 | 独立管理员登录后操作 |

收到的评价列表不标注评价者姓名，原文会按提交内容展示。庭院接口只返回共享摘要和投票统计。

密码采用带独立随机盐的 scrypt 哈希保存。登录会话使用 HttpOnly、SameSite Cookie。普通用户会话有效期为 24 小时，管理员后台为 2 小时。重置同事密码或停用账号会使该账号已有会话失效。

应用数据默认位于 `.huping-data/`，包含账号、会话、草稿、已提交评价和汇总。该目录已被 Git 忽略。备份可在服务停止后复制整个目录；使用自定义数据库路径时，也应为对应文件设置备份和 Git 忽略规则。

## 项目结构

```text
.
├── index.html       # 用户界面、登录入口和房间弹层
├── styles.css       # 共享样式、玻璃效果和响应式布局
├── accounts.js      # 普通用户登录、退出和账号菜单
├── app.js           # 房间切换、互评、个人报告和同事广场
├── admin.html       # 管理员登录和账号管理页面
├── admin.js         # 管理员会话、账号编辑、搜索与分页
├── server.mjs       # 本地 HTTP 服务、API 路由和 GPT 分析
├── data.mjs         # SQLite 数据、账号、会话和互评查询
├── deploy/          # 服务配置、环境变量模板、备份脚本和部署说明
└── assets/          # 四个房间的 WebP 背景
```

背景素材由图像生成制作，页面交互和毛玻璃效果由 HTML、CSS 和 JavaScript 实现。

## 检查与当前范围

可以在仓库根目录执行语法检查。

```sh
node --check accounts.js
node --check admin.js
node --check app.js
node --check data.mjs
node --check server.mjs
node --test tests/review-history.test.mjs
```

开发中已进行浏览器交互验证，覆盖登录与账号权限、互评保存、报告汇总、列表搜索和分页，以及桌面和手机布局。评价历史回归测试使用临时数据库，覆盖旧数据迁移、多次提交、重试去重、历史分页、来源人数去重和分析归属，不改动本地或线上数据。

服务监听 `127.0.0.1`。本地默认只接受本机 Host；远程部署时配置 `PUBLIC_ORIGIN`，由 HTTPS 反向代理转发请求。完整应用需要运行 Node.js 服务和 SQLite，GitHub Pages 无法承载这些后端功能。

服务器目录、服务与更新方法见 [部署说明](deploy/README.md)。当前应用没有登录限流和操作审计。
